# Integrating myMPD

myMPD is the Phase 2 web UI. It is the first thing in this image that is
somebody else's project with its own build system, so it does not go through
`board/slmp/post-build.sh` the way `bdp-panel` does. It is a proper Buildroot
package in a `BR2_EXTERNAL` tree, built from the `src/mympd` submodule.

This document is the record of what that took: every file created, every file
edited, and the reasoning behind the choices that are not obvious. Where a
decision was forced by the hardware or by something in myMPD's own build, that
is stated rather than left for the next person to rediscover.

---

## Summary of what was decided

| Question | Answer | Why |
| --- | --- | --- |
| Package or post-build hook? | `BR2_EXTERNAL` package | It has a CMake build, dependencies and an install step. `post-build.sh` is for our own source, where the whole build is one `make`. |
| Source | `src/mympd` submodule, `SITE_METHOD = local` | Tracks a fork, and the pin is the submodule commit rather than a tarball hash. |
| `CMAKE_BUILD_TYPE` | `None`, not `Release` | `Release` turns on `-fcf-protection=full`, which emits `ENDBR32`. See below — this is the one that matters. |
| In-source build | disabled | myMPD's asset generator deletes the `htdocs` it then reads from. |
| `BUILD_SHARED_LIBS` | `OFF` | Buildroot's `ON` turns myMPD's five bundled `dist/` libraries into `.so` files that nothing installs. |
| libmpdclient | myMPD's bundled copy | Buildroot ships 2.22, myMPD wants 2.26. |
| TLS | off | A self-signed cert the browser rejects, generated by a 500 MHz CPU, protecting a LAN appliance that also runs telnetd. |
| Port | 80, running as root | Decided, not deferred. Consistent with MPD and telnetd, and the exposure is a LAN-only appliance. |
| Work directory | `/data/mympd` on the persistent partition | Settings survive a reboot. The cache stays on tmpfs so cover art cannot wear the CF card. See [storage.md](storage.md). |
| Lua, IPv6, utf8proc | off | Scripting is not wanted on an appliance, the unit is IPv4-only, and utf8proc is a dependency for a feature nobody here will notice. |
| FLAC, libid3tag | on | Embedded albumart and lyrics. FLAC is already in the image for MPD, so it is free; libid3tag is about 100 KB. |
| PCRE2 JIT | off | A runtime code generator is the one thing the NOPL scan cannot inspect. |

## The thing that would have bitten: ENDBR32

This is the whole reason the package file has forty lines of comment in it.

myMPD's `CMakeLists.txt` applies a large hardening flag set for every build
type it recognises, and it feature-tests each flag with
`check_c_compiler_flag` before adding it. One of them is
`-fcf-protection=full`. The Buildroot toolchain accepts that flag, so it gets
added, and GCC then emits `ENDBR32` at every function entry:

```bash
$ i586-buildroot-linux-musl-gcc -O2 -c t.c && objdump -d t.o | grep -c endbr32
0
$ i586-buildroot-linux-musl-gcc -O2 -fcf-protection=full -c t.c && objdump -d t.o | grep -c endbr32
2
```

`ENDBR32` is `F3 0F 1E FB`. The long NOP that this entire project exists to
avoid — the one instruction an i686 build has that the Geode LX does not — is
`0F 1F`. `ENDBR32` is `0F 1E`, the adjacent opcode in the same reserved-NOP
group. A CPU that raises `#UD` on `0F 1F` cannot be assumed to decode `0F 1E`,
and finding out on the bench costs a reflash.

Appending `-fcf-protection=none` to `CFLAGS` does not fix it. CMake puts
`add_compile_options()` after `CMAKE_C_FLAGS` on the command line, so the last
`-fcf-protection` GCC sees is still `=full`.

What does fix it is taking upstream at its word. The hardening block ends with:

```cmake
else()
  # if CMAKE_BUILD_TYPE is neither Release nor Debug,
  # do not alter compile options
endif()
```

So the package passes `-DCMAKE_BUILD_TYPE=None`. What is lost is only what
Buildroot already supplies from the defconfig — `-O2` from `BR2_OPTIMIZE_2`,
`-fPIE` from `BR2_PIC_PIE`, relro/now from `BR2_RELRO_FULL`, stripping from
`BR2_STRIP_strip` — plus upstream's `-Werror`, which is not something to
inherit when building someone else's C with a compiler they did not test
against.

The scan in `phase 1.sh` was only looking for `nopl`, so it would not have
caught this. It now looks for the whole group, and it aborts rather than
warning. That change is in the edits below.

## The other thing: Install.cmake writes to the build host

`cmake/Install.cmake.in` installs manpages, documentation and the init script
with `file(INSTALL ...)` to **absolute paths** — `/usr/lib/systemd/system`,
`/etc/init.d`, `CMAKE_INSTALL_FULL_MANDIR`. `file(INSTALL)` does not prefix
`DESTDIR`. Worse, it chooses the init system by probing the *build host*:

```cmake
if(EXISTS "/lib/systemd/system" OR EXISTS "/usr/lib/systemd/system")
  install_systemd()
elseif(EXISTS "/etc/init.d")
  install_sysvinit()
```

Left enabled in a cross build, that writes into the build machine's own
filesystem. `MYMPD_DOC`, `MYMPD_DOC_HTML`, `MYMPD_MANPAGES` and
`MYMPD_STARTUP_SCRIPT` are therefore all `OFF` — not to save space in the
image, though they do that too.

## The third thing: an in-source build deletes the web UI

Buildroot builds CMake packages **in-source** unless a package sets
`_SUPPORTS_IN_SOURCE_BUILD = NO` (`package/pkg-cmake.mk:54`). That makes
`CMAKE_CURRENT_BINARY_DIR` the source directory, and myMPD's asset generator
begins with:

```sh
rm -fr "$MYMPD_BUILDDIR/htdocs"
install -d "$MYMPD_BUILDDIR/htdocs/js"
```

so it deletes the `htdocs` tree it is about to read `index.html` out of. The
configure step then fails as:

```
Creating assets in .../output/build/mympd-26.1.0
Validating translation phrases
Creating i18n json
Error creating translation files
CMake Error at CMakeLists.txt:262 (message):
  Creating assets failed
```

which names neither the file nor the reason, because `build.sh` calls
`createi18n 2>/dev/null`. The actual error only appears if you run the Perl by
hand in the build directory:

```
Can't open file "htdocs/index.html": No such file or directory
```

`MYMPD_SUPPORTS_IN_SOURCE_BUILD = NO` moves the build to
`$(@D)/buildroot-build` and the problem goes away. Note that the submodule in
`src/mympd` is never at risk: the `local` site method rsyncs it into
`output/build/` first, so what gets destroyed is the copy.

## The fourth thing: five shared libraries that nobody installs

myMPD bundles mongoose, mpack, rax, sds and libmpdclient under `dist/` and
declares each with a bare `add_library(name "")` — no `STATIC`, no `SHARED`.
Upstream builds them static because CMake defaults that way. Buildroot passes
`-DBUILD_SHARED_LIBS=ON` for every package unless the whole image is static,
which flips all five to shared objects that myMPD's install step knows nothing
about. The build succeeds and the binary is unrunnable:

```
$ readelf -d target/usr/bin/mympd | grep NEEDED
 Shared library: [libmpack.so]
 Shared library: [libmongoose.so]
 Shared library: [librax.so]
 Shared library: [libsds.so]
 ...
$ ls target/usr/lib/libmpack.so
ls: No such file or directory
```

The bundled libmpdclient is the dangerous one rather than the merely broken
one. It is `libmpdclient.so` with no version suffix, and `mpc` has already put
Buildroot's `libmpdclient.so -> libmpdclient.so.2.22` in `/usr/lib`. The
dynamic linker would have satisfied myMPD with the 2.22 it was not compiled
against — an ABI mismatch that surfaces as a crash somewhere unrelated, not as
a missing-library error.

`-DBUILD_SHARED_LIBS=OFF` links all five into the binary and removes both
problems. After it, the only `NEEDED` entries are real system libraries:

```
libpcre2-8.so.0  libssl.so.3  libcrypto.so.3  libid3tag.so.0  libFLAC.so.12  libc.so
```

## Prerequisite: the submodule

```bash
git submodule update --init --recursive
```

`src/mympd` is a submodule pointing at a fork over SSH, so a clone without
credentials gets an empty directory. Buildroot's `local` site method will
rsync that empty directory quite happily and then fail much later with a CMake
error that says nothing about submodules, so `phase 1.sh` now checks for it up
front.

## Files created

### `br2-external/external.desc`

Names the tree. The name becomes `BR2_EXTERNAL_SLMP_PATH`, which the package
uses to find the source.

```
name: SLMP
desc: super_lite_music_player packages
```

### `br2-external/Config.in`

Adds the menu to `make menuconfig`.

```
menu "super_lite_music_player"

source "$BR2_EXTERNAL_SLMP_PATH/package/mympd/Config.in"

endmenu
```

### `br2-external/external.mk`

Pulls in every package `.mk` in the tree, so adding a second package later
needs no edit here.

```make
include $(sort $(wildcard $(BR2_EXTERNAL_SLMP_PATH)/package/*/*.mk))
```

### `br2-external/package/mympd/Config.in`

```
config BR2_PACKAGE_MYMPD
	bool "mympd"
	depends on BR2_USE_MMU
	depends on BR2_TOOLCHAIN_HAS_THREADS
	select BR2_PACKAGE_OPENSSL
	select BR2_PACKAGE_PCRE2
	help
	  myMPD is a standalone web UI for the Music Player Daemon.
	  It embeds its own web server, so nothing else is needed to
	  serve it.

	  Built from the checkout in src/mympd, not from a release
	  tarball, so the version in the image is whatever that
	  submodule is pinned to.

	  https://jcorporation.github.io/myMPD/

if BR2_PACKAGE_MYMPD

config BR2_PACKAGE_MYMPD_FLAC
	bool "flac support"
	select BR2_PACKAGE_FLAC
	help
	  Read albumart and lyrics embedded in FLAC files.

config BR2_PACKAGE_MYMPD_LIBID3TAG
	bool "libid3tag support"
	select BR2_PACKAGE_LIBID3TAG
	help
	  Read albumart and lyrics embedded in ID3v2 tags.

endif

comment "mympd needs a toolchain w/ threads"
	depends on BR2_USE_MMU
	depends on !BR2_TOOLCHAIN_HAS_THREADS
```

OpenSSL and PCRE2 are `select`ed rather than `depends on` because myMPD's
CMakeLists declares both `REQUIRED` — there is no build without them, so
there is no point offering a configuration that cannot work.

### `br2-external/package/mympd/mympd.mk`

The comments are load-bearing; they are the reason each option is set, and
three of the four hard problems in this integration are recorded in them.

```make
################################################################################
#
# mympd
#
################################################################################

# Built from the submodule in src/mympd, not from an upstream tarball,
# so there is no hash to verify and no version to bump here: the pin is
# the submodule commit. This string only names the build directory.
MYMPD_VERSION = 26.1.0
MYMPD_SITE = $(BR2_EXTERNAL_SLMP_PATH)/../src/mympd
MYMPD_SITE_METHOD = local
MYMPD_LICENSE = GPL-3.0+
MYMPD_LICENSE_FILES = LICENSE.md

# host-jq, because myMPD runs its own build.sh at CMake configure time
# to minify and gzip the web assets, and that needs jq for the i18n
# JSON. Depending on the package rather than on whatever the developer
# happens to have installed keeps the build reproducible: BR_PATH puts
# $(HOST_DIR)/bin first, so this jq wins even on a host that has one.
# perl and gzip, which build.sh also needs, are host requirements the
# top-level script already checks for.
MYMPD_DEPENDENCIES = host-jq openssl pcre2

# Out-of-source, and not as a matter of taste. Buildroot builds CMake
# packages in-source unless told otherwise, which here means
# CMAKE_CURRENT_BINARY_DIR is the source directory, and myMPD's asset
# generator opens with:
#
#     rm -fr "$$MYMPD_BUILDDIR/htdocs"
#
# In an in-source build that deletes the htdocs it is about to read
# index.html from, and the configure step fails inside a subshell whose
# stderr build.sh has redirected to /dev/null. The visible error is
# "Creating assets failed", which says nothing about the cause.
MYMPD_SUPPORTS_IN_SOURCE_BUILD = NO

# CMAKE_BUILD_TYPE=None is the whole reason this package is not three
# lines long.
#
# myMPD's CMakeLists.txt applies a large hardening flag set for every
# build type it recognises, and feature-tests each flag with
# check_c_compiler_flag before adding it. One of them is
# -fcf-protection=full, which this toolchain accepts and which makes
# GCC emit ENDBR32 (F3 0F 1E FB) at every function entry. ENDBR32 sits
# in the 0F 1E slot, one opcode below the long NOP (0F 1F) that the
# Geode LX does not implement and that this entire project exists to
# avoid. A CPU that raises #UD on 0F 1F cannot be assumed to decode
# 0F 1E either, and appending -fcf-protection=none to CFLAGS does not
# help: add_compile_options() lands after CMAKE_C_FLAGS, so the last
# flag on the command line is still =full.
#
# The upstream CMakeLists ends that block with "if CMAKE_BUILD_TYPE is
# neither Release nor Debug, do not alter compile options". Taking it at
# its word is cheaper and more honest than patching it. We lose only
# flags Buildroot already supplies: -O2 from BR2_OPTIMIZE_2, -fPIE from
# BR2_PIC_PIE, relro/now from BR2_RELRO_FULL, and the strip from
# BR2_STRIP_strip. It also drops upstream's -Werror, which is not
# something to inherit when building someone else's C with a compiler
# they did not test.
MYMPD_CONF_OPTS = \
	-DCMAKE_BUILD_TYPE=None \
	-DBUILD_SHARED_LIBS=OFF \
	-DMYMPD_BUILD_TESTING=OFF \
	-DMYMPD_DOC=OFF \
	-DMYMPD_DOC_HTML=OFF \
	-DMYMPD_MANPAGES=OFF \
	-DMYMPD_STARTUP_SCRIPT=OFF \
	-DMYMPD_EMBEDDED_ASSETS=ON \
	-DMYMPD_EMBEDDED_LIBMPDCLIENT=ON \
	-DMYMPD_ENABLE_IPV6=OFF \
	-DMYMPD_ENABLE_LUA=OFF \
	-DMYMPD_ENABLE_UTF8=OFF

# BUILD_SHARED_LIBS=OFF overrides Buildroot, which passes ON for every
# CMake package unless the whole image is static. myMPD bundles mongoose,
# mpack, rax, sds and libmpdclient in dist/ and declares them with a bare
# add_library(), so ON turns all five into shared objects. It then
# installs none of them, because upstream builds them static and has
# never needed to. The result links, installs, and dies at exec with
# "libmpack.so: No such file or directory".
#
# The bundled libmpdclient is worse than merely missing. It is
# libmpdclient.so with no version suffix, and mpc has already put
# Buildroot's libmpdclient.so -> libmpdclient.so.2.22 in /usr/lib. The
# binary would have resolved against the 2.22 it was not compiled
# against, which is an ABI mismatch that shows up as a crash somewhere
# unrelated rather than as a link error. Static bundling removes the
# collision along with the missing files.

# MYMPD_DOC, MYMPD_MANPAGES and MYMPD_STARTUP_SCRIPT are not off to save
# space. They are off because cmake/Install.cmake.in installs them with
# file(INSTALL) to absolute paths that DESTDIR does not prefix, and it
# picks the init system by probing the *host* for /usr/lib/systemd or
# /etc/init.d. Left on, a cross build writes into the build machine's
# own filesystem.

# Buildroot's libmpdclient is 2.22 and myMPD wants 2.26. Left to itself
# myMPD finds the staging copy, warns, and silently falls back to the
# one it bundles. Asking for the bundled one outright means the outcome
# does not depend on what else happens to be in staging.

ifeq ($(BR2_PACKAGE_MYMPD_FLAC),y)
MYMPD_DEPENDENCIES += flac
MYMPD_CONF_OPTS += -DMYMPD_ENABLE_FLAC=ON
else
MYMPD_CONF_OPTS += -DMYMPD_ENABLE_FLAC=OFF
endif

ifeq ($(BR2_PACKAGE_MYMPD_LIBID3TAG),y)
MYMPD_DEPENDENCIES += libid3tag
MYMPD_CONF_OPTS += -DMYMPD_ENABLE_LIBID3TAG=ON
else
MYMPD_CONF_OPTS += -DMYMPD_ENABLE_LIBID3TAG=OFF
endif

# No work directory is created here. myMPD's compiled-in default is
# /var/lib/mympd, which is on the read-only root; /etc/default/mympd
# points it at /data/mympd instead, and /etc/init.d/S03data creates that
# on the persistent partition before anything needs it.

$(eval $(cmake-package))
```

Three details in there that are not guessable:

- **`MYMPD_EMBEDDED_ASSETS=ON`** puts the whole web UI inside the binary. On a
  read-only root with no document root to serve from, that is the only sane
  option, and it is upstream's default for non-Debug builds anyway.
- **`MYMPD_EMBEDDED_LIBMPDCLIENT=ON`** is not a preference. Buildroot 2025.02.9
  ships libmpdclient 2.22; myMPD's minimum is 2.26. Left to itself, myMPD finds
  the staging copy, warns that it is too old, and falls back to its bundled
  one. Asking outright means the result does not depend on what else happens to
  be in staging — `mpc` puts libmpdclient there whether myMPD wants it or not.
- **No work directory is created here.** myMPD's compiled-in default is
  `/var/lib/mympd`, on the read-only root. `/etc/default/mympd` points it at
  `/data/mympd` and `S03data` creates that — see [storage.md](storage.md).

### `board/slmp/rootfs-overlay/etc/default/mympd`

myMPD has no config file. It keeps one small file per setting under
`<workdir>/config`, and on every start it reads the environment first: if
`MYMPD_<SETTING>` is set, the matching file is deleted and rewritten from the
environment. The work directory is on `/data`, so settings changed in the web
UI now persist — but anything exported here still overwrites them on every
start. Export a setting to pin it; leave it out to let the web UI own it.

```sh
# Settings on the data partition; regenerable caches in RAM.
MYMPD_WORKDIR="/data/mympd"
MYMPD_CACHEDIR="/tmp/mympd-cache"

export MYMPD_HTTP=true
export MYMPD_HTTP_PORT=80
export MYMPD_SSL=false

export MYMPD_CACHE_COVER_KEEP_DAYS=0
export MYMPD_CACHE_THUMBS_KEEP_DAYS=0
export MYMPD_CACHE_LYRICS_KEEP_DAYS=0
export MYMPD_CACHE_HTTP_KEEP_DAYS=0

MYMPD_SYSLOG=1
MYMPD_ARGS=""
```

(The file in the tree carries the full commentary; this is the settings
themselves.) Two kinds of variable live here and the distinction matters: the
exported ones are myMPD's own, named `MYMPD_<setting>` after its config items;
the unexported ones are read by the init script and mean nothing to the binary.
myMPD has no config item called `workdir`, `cachedir`, `syslog` or `args`, so
the two namespaces do not collide.

The disk caches are `0`, which disables them — `-1` would mean "keep forever".
The cache directory is on tmpfs and therefore in the 256 MB of RAM the unit
has, and cover art is the one that grows without an obvious bound. The cost is
re-reading artwork from the files each time it is displayed. The cache
deliberately did not follow the work directory onto `/data`: it is
regenerable, and writing cover art to a CF card continuously is how the card
dies.

### `board/slmp/rootfs-overlay/etc/init.d/S96mympd`

`S96`, so after Buildroot's `S95mpd`. myMPD does not need MPD to be up — it
reconnects on its own — but starting second means the first thing the UI shows
is a connected player rather than an error.

```sh
#!/bin/sh
DAEMON=/usr/bin/mympd
PIDFILE=/var/run/mympd.pid

MYMPD_WORKDIR="/data/mympd"
MYMPD_CACHEDIR="/tmp/mympd-cache"
MYMPD_SYSLOG=1
MYMPD_ARGS=""

set -a
[ -r /etc/default/mympd ] && . /etc/default/mympd
set +a

start() {
	printf 'Starting myMPD: '
	if ! mkdir -p "$MYMPD_WORKDIR" "$MYMPD_CACHEDIR"; then
		echo "FAIL (cannot create $MYMPD_WORKDIR - did S03data run?)"
		return 1
	fi
	[ "$MYMPD_SYSLOG" = "1" ] && set -- -s
	start-stop-daemon -S -q -b -m -p "$PIDFILE" -x "$DAEMON" -- \
		-w "$MYMPD_WORKDIR" -a "$MYMPD_CACHEDIR" "$@" $MYMPD_ARGS
	if [ $? = 0 ]; then echo OK; else echo FAIL; fi
}
```

`set -a` around the source is the point of the script. Most of what
`/etc/default/mympd` sets is myMPD's own configuration and has to reach the
daemon's *environment*, not just this shell — unlike `/etc/default/bdp-panel`,
which only builds an argument string. The `mkdir -p` covers the cache
directory, which is a fresh tmpfs on every boot; the work directory is made by
`S03data` on the persistent partition. myMPD creates its own subdirectories
under both, but not these two roots.

## Files edited

### `configs/slmp_defconfig`

Added, between the audio and diagnostics sections:

```diff
+# --- Web UI ------------------------------------------------------------
+# myMPD, from the submodule in src/mympd, via the BR2_EXTERNAL tree in
+# br2-external/. It selects openssl and pcre2, which it hard-requires.
+BR2_PACKAGE_MYMPD=y
+# Albumart and lyrics embedded in the files themselves. flac is already
+# in the image for MPD, so that one is free; libid3tag is not, and is
+# about 100 KB.
+BR2_PACKAGE_MYMPD_FLAC=y
+BR2_PACKAGE_MYMPD_LIBID3TAG=y
+# No BR2_PACKAGE_PCRE2_JIT. The JIT generates machine code at runtime,
+# which is exactly the thing the NOPL check in phase 1.sh cannot see,
+# and sljit's x86-32 backend is not something to trust on a CPU this
+# old. The interpreter is fast enough for search patterns.
```

`BR2_PACKAGE_OPENSSL` and `BR2_PACKAGE_PCRE2` are deliberately absent: the
package `select`s them, and listing a selected symbol in a defconfig is how you
end up with a defconfig that disagrees with itself.

### `board/slmp/rootfs-overlay/etc/fstab`

myMPD originally got a 32 MB tmpfs of its own at `/var/lib/mympd`. That line
is gone: the work directory moved to the persistent partition and the cache
moved to `/tmp`. The fstab changes that replaced it are in
[storage.md](storage.md).

### `phase 1.sh`

Three changes.

**1. The external tree, declared next to the board directory:**

```diff
+# Packages that are ours rather than Buildroot's live in a BR2_EXTERNAL
+# tree. Unlike the board directory this is not symlinked in: Buildroot
+# takes it as a make variable and records it in the output directory, so
+# it only has to be passed when the configuration is applied. Every
+# later "make -C" reads it back from output/.br2-external.mk.
+BR2_EXTERNAL_DIR="$SCRIPT_DIR/br2-external"
```

and passed exactly once, where the configuration is applied:

```diff
-make -C "$BR_DIR" "${BOARD_NAME}_defconfig"
+make -C "$BR_DIR" BR2_EXTERNAL="$BR2_EXTERNAL_DIR" "${BOARD_NAME}_defconfig"
```

This is why `make -C output/slmp-build/buildroot-2025.02.9` still works for
iteration with no extra arguments: Buildroot writes the value into
`output/.br2-external.mk` and reads it back on every subsequent invocation.

**2. An up-front check that the submodule is populated**, next to the existing
board-directory checks, because the failure mode otherwise is a CMake error
forty minutes in that does not mention submodules.

**3. The instruction scan now covers the whole opcode group and aborts:**

```diff
-    for b in bin/busybox usr/bin/mpd; do
-        n="$(printf '%s\n' "$dis" | grep -c '\<nopl\>' || true)"
+GEODE_BAD='\<(nopl|endbr32|endbr64)\>'
+    for b in bin/busybox usr/bin/mpd usr/bin/mympd usr/bin/bdp-panel; do
+        n="$(printf '%s\n' "$dis" | grep -cE "$GEODE_BAD" || true)"
```

It now prints a per-instruction count when it finds something and calls `die`
instead of `warn`. A binary that cannot execute is not a warning. `bdp-panel`
is in the list too — it was never covered, despite `src/panel/Makefile` having
had a `check-geode` target all along that the build never invoked.

## Commands

Everything, from a clean checkout:

```bash
git submodule update --init --recursive
./phase\ 1.sh
```

Iterating on the myMPD package itself, which is what you will actually be
doing:

```bash
BR=output/slmp-build/buildroot-2025.02.9

# after editing mympd.mk or the defconfig: reapply the configuration
cp configs/slmp_defconfig $BR/configs/
make -C $BR BR2_EXTERNAL=$PWD/br2-external slmp_defconfig

# rebuild just myMPD and everything it needs
make -C $BR mympd

# force a full reconfigure and rebuild of the package alone
make -C $BR mympd-dirclean mympd

# then repack the rootfs and the image
make -C $BR
```

`mympd-rebuild` re-runs the build step but not CMake, so it will not pick up a
changed `MYMPD_CONF_OPTS`. Use `mympd-reconfigure` for that, or `mympd-dirclean`
when in doubt — the source is rsynced from `src/mympd` again either way, so
nothing is lost.

Checking what the flags actually did:

```bash
# should print nothing at all
$BR/output/host/bin/i586-linux-objdump -d $BR/output/target/usr/bin/mympd \
  | grep -E '\<(nopl|endbr32)\>'

# what got linked, and how big it came out
$BR/output/host/bin/i586-linux-readelf -d $BR/output/target/usr/bin/mympd | grep NEEDED
ls -l $BR/output/target/usr/bin/mympd
```

## What the build actually produced

From a clean `./phase 1.sh` run with everything above in place:

```
==> Checking target binaries for instructions the Geode LX lacks
  bin/busybox      177927 instructions, clean
  usr/bin/mpd      250676 instructions, clean
  usr/bin/mympd    185504 instructions, clean
  usr/bin/bdp-panel 1234 instructions, clean
==> Done
  image:  .../output/images/sdcard.img
  size:   465M to write (42M allocated, the file is sparse)
```

No defconfig, kernel-fragment or BusyBox-fragment symbol was dropped. The
image grew from 33 MB allocated to 42 MB; OpenSSL is most of that, and the
`mympd` binary itself is 1.6 MB with the web UI embedded in it.

What myMPD installed into the target, and nothing else:

```
/usr/bin/mympd
/usr/bin/mympd-config
```

**It has now run on the hardware, and it failed.** Not for any reason in this
document: `/data` did not exist as a directory in the image, so myMPD could not
create its work directory on the read-only root and exited:

```
ERROR    mympd      Work dir: creating "/data/mympd" failed
ERROR    mympd      No such file or directory
```

The cause was a missing mountpoint, fixed in `post-build.sh` — the write-up is
in [storage.md](storage.md#what-the-first-hardware-run-found). What this does
establish is that the binary runs on a Geode LX at all: it loaded, parsed its
arguments, resolved every shared library, logged through its own logger and
exited on a real error rather than on an illegal instruction. The `-O2`-only,
CET-free build works.

Two further things came out of poking at it on the unit.

**Running `mympd` by hand went somewhere else entirely.** With no arguments it
uses its compiled-in defaults — `/var/lib/mympd` and `/var/cache/mympd` — not
the paths the init script passes, so it produced forty lines of "Read-only file
system" pointing at a directory nothing had been configured to use. That is a
trap for whoever is debugging at the time, so `/var/lib/mympd` is now a symlink
to `/data/mympd` in the overlay, and `MYMPD_CACHEDIR` is now
`/var/cache/mympd`, which the skeleton already symlinks to `/tmp`. A bare
`mympd` and the service now write to exactly the same places.

### The missing CA store stops myMPD from starting

There are **two** different "CA cert store not found" EMERGs, and confusing
them cost a boot. The first is harmless; the second is fatal.

**The harmless one** comes from computing the default value of
`ca_cert_store`. The call site is unconditional and runs before the
environment is read, so no setting can silence it:

```c
case CI_CA_CERT_STORE: def = find_ca_cert_store(false); break;
```

**The fatal one** is `System certificate store not found.`, from
`mympd_read_ca_certificates()`, and `main.c:342` treats a false return as a
startup failure. On a BDP-1 myMPD got all the way to
`Listening on http://0.0.0.0:80` and then exited:

```
EMERG  mympd: System certificate store not found.
NOTICE mympd: Exiting erroneous, thank you for using myMPD
```

The fix is the first three lines of that function:

```c
bool mympd_read_ca_certificates(struct t_config *config) {
    if (config->cert_check == false) {
        return true;
    }
```

So `MYMPD_CERT_CHECK=false`, which is not the security decision it looks like.
What it disables is certificate verification for **outbound** connections, and
this image makes no outbound TLS connections at all: `MYMPD_WEBRADIODB=false`
turns off the one feature that phones home by itself, and the script-driven
ones — lyrics fetching, ListenBrainz, fanart — cannot run because Lua is
compiled out. It switches off verification of connections that do not happen.

The image ships no CA bundle on purpose; the proposal argues against trusting
the public CA system with a frozen bundle that expires years after anyone is
thinking about it. If outbound HTTPS is ever wanted, the answer is to point
`ca_cert_store` at a pinned certificate, which is Phase 4's job.

With that set, on a real BDP-1:

```
$ curl -s --compressed http://192.168.0.138/ | head -c 60
<!DOCTYPE html><!--myMPD (c) 2018-2026 Juergen Mang
status=200  bytes=17781  time=0.015s
```

and the JSON-RPC API answers with live MPD state:

```json
{"jsonrpc":"2.0","id":0,"result":{"method":"MYMPD_API_PLAYER_STATE",
 "state":"stop","partition":"default", ...}}
```

myMPD logs `Connected to MPD`, settings appear under `/data/mympd/config`, and
the whole unit sits at 9 MB of 228 MB used. Serving the embedded UI takes 15 ms.

Still untested: the first scan of a real library, and what that costs on a
500 MHz CPU.

## On the unit

```
http://<ip>/
```

Login is unchanged. Useful checks if it does not come up:

```bash
grep mympd /var/log/messages  # it logs to syslog, see /etc/default/mympd
                              # there is no logread applet in this image:
                              # CONFIG_FEATURE_IPC_SYSLOG is off, so busybox
                              # syslogd writes to a file, and /var/log is a
                              # symlink to /tmp
mount | grep mympd            # the tmpfs must be there before S96 runs
ls /data/mympd/config         # one file per setting, written on first start
/etc/init.d/S96mympd restart
mympd -v                      # version, and which optional libraries are in
```

`mympd-config` is installed as well; it is upstream's POSIX-sh helper for
editing those config files in place, and it works under BusyBox ash.

## Decisions and limitations

**Running as root on port 80 is a decision, not an oversight.** myMPD 26 has
no privilege-dropping option, and port 80 needs root. A dedicated user on
port 8080 was considered and rejected: this is a LAN appliance that already
runs telnetd and MPD as root, so a web server is not the weak link, and a unit
reachable by an attacker already implies a compromised home network. The
ergonomics of `http://<ip>/` are worth more here than a hardening step that
would not change the outcome. Revisit if the unit ever faces anything but a
home LAN.

**Settings persist, within limits.** The work directory is on `/data`, so
changes made in the web UI survive a power cycle — but anything *exported* in
`/etc/default/mympd` is reapplied on every start and overwrites the stored
value. Export a setting to pin it; leave it out to let the web UI own it. If
`/data` could not be mounted, `S03data` substitutes a tmpfs and the old
lose-everything-on-reboot behaviour silently returns, with a warning in the
log. See [storage.md](storage.md).

**The album cache is rebuilt on every boot.** It lives under the work
directory, so it is on `/data` and could persist, but the disk caches are
switched off — they are the one thing here that grows without a bound, and the
cache directory is deliberately a tmpfs so that turning one back on cannot
start writing cover art to the CF card continuously.

**Outbound HTTPS features are still compiled in.** TODO.md asks for lyrics
fetching, ListenBrainz, fanart and the webradio directory to be compiled out.
myMPD 26 has no build options for those individually; they are runtime settings
and `cert_check` is on by default. Turning them off belongs in
`/etc/default/mympd` once the exact setting names are confirmed against a
running unit.
